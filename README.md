## Week 1 — API Incident Explorer

**▶ [Open the live app](https://arunrps-api-incident-explorer.streamlit.app)**

**Theme:** Data Analysis with Vibe Coding · **Path B** (own application)

*From traffic signals to an investigation shortlist.*

Turns synthetic API gateway logs into an investigation shortlist: which endpoint is
failing, which backend service is the suspect, which consumer is worst affected, and
what to check next. Framed deliberately as an **investigation aid / suspect ranking**,
never "root cause analysis" — the app ranks and correlates, the engineer concludes.

### What it does

- **Incident Brief** — a deterministic plain-English summary generated by pandas
  aggregations and an f-string. No language model is involved, so every claim traces
  back to a number visible elsewhere on the page. If the filtered window shows nothing
  elevated, it says so plainly instead of inventing an incident.
- **4 KPI cards** — total requests, 5xx error rate, p95 response time, consumers affected
- **2 time-series charts** — 5xx error rate and p95 latency in 5-minute buckets
- **Top Suspects table** — endpoint + backend pairs ranked by 5xx rate, with supporting
  request counts, p95 and failed-request columns. Plain sorting, no invented composite
  score, so every figure is defensible.
- **Sidebar filters** — time range, endpoint, backend service, consumer

### The data

`generate_data.py` produces 50,000 seeded, byte-reproducible rows covering 09:00–15:00,
using the Python standard library only. A realistic incident is deliberately injected —
random data would have produced random charts and no story to investigate.

| Phase | Window | Requests | /checkout p95 | /checkout 5xx |
|---|---|---|---|---|
| Baseline | 09:00–13:55 | 41,961 | 250 ms | 0.4% |
| Early warning | 13:55–14:05 | 1,377 | 634 ms | 0.0% |
| Incident | 14:05–14:45 | 4,979 | 2,163 ms | 18.4% |
| Recovery | 14:45–15:00 | 1,683 | 1,577 ms | 4.4% |

Design details that make the dataset worth investigating:

- **Latency leads errors.** p95 climbs for ten minutes before any 5xx appears — the
  leading-indicator signature a real on-call engineer looks for.
- **A deployment correlates but does not prove.** `payment-service` moves v2.4.0 → v2.4.1
  at 13:50. There is **no rollback**, so recovery cannot be read as confirmation of cause.
- **Two endpoints share a backend.** `/checkout` and `/refunds` both sit on
  `payment-service` and degrade together, so the table can distinguish an endpoint
  problem from a backend problem.
- **A red herring.** `/search` has the highest request volume and visibly jittery latency
  but a ~0.05% error rate — high volume is not the same as high risk.

### Run locally

```
cd week-01
pip install -r requirements.txt
streamlit run app.py
```

Then open http://localhost:8501

The data path is resolved against the location of `app.py` rather than the working
directory, so the app also runs from the repository root with
`streamlit run week-01/app.py` — which is how it is launched in deployment.
